如果你在群里用 save_it 存图存视频，这一版的三件事你应该立刻能感觉到。

<Highlight label="重点 01" title="保存的 GIF 变成能播的动图">

以前保存一个 GIF（比如 X 上的 GIF 帖子），Telegram 里收到的是一个需要点开下载的文件附件，聊天窗口里看不到动画；超过上传上限的 GIF 甚至直接发不出来。

现在 save_it 会在上传前把 GIF 本地转成 Telegram 友好的 mp4（libx264 / yuv420p / faststart，并读出宽高时长），再作为 animation 发送。副作用很实际：大 GIF 转码后体积通常小一个数量级，原本「文件过大」发不出去的 GIF 现在也能发出来。ffmpeg 不可用或转码失败时，会退回发送原始 GIF，不会因此丢消息。

<Highlight label="重点 02" title="/detail 更名为 /info">

回复任意一张已保存的图片或视频，发送 `/info`，bot 会返回这条媒体的来源信息：原始消息链接、原始 URL、caption、标题、描述、关键词、保存时间（缺失的字段自动省略）。

命令语义和输出没变，只是名字更短、更符合直觉。`/detail` 已不再受支持，请改用 `/info`。

<Highlight label="重点 03" title="离线期间的链接不再丢">

以前 bot 离线时你连发了几个链接，重启后只有最新那条会被处理，前面的会被 Telegram 的更新队列丢掉。

原因是默认轮询在启动时用了 `offset: -1`，而负数 offset 对 Telegram 来说是一个「丢弃旧更新」的破坏性操作。现在 save_it 用自己的轮询器：启动后的第一次 `getUpdates` 不带 offset，把队列里最早的未确认更新全部取回并逐条处理，处理完再用 `max(update_id) + 1` 确认。

## 更小的改进

- Telegram 限流时，链接保存会自动重试一次，并在聊天里告知重试时间，而不是静默失败。
- Google Drive 备份改用可续传上传，大文件在超时后可以恢复；上传成功、失败、以及「未配置 Drive 所以跳过」都会写进运行日志。
- Google Drive 登录在 OAuth 客户端配置被拒时可自行恢复：清理卡住的 pending device code，并给出可操作的配置提示。

## 已知限制

- 短语义查询（例如 `/search girl`）仍可能有误命中，这是当前 Typesense 图片向量模型的限制。
- 视频上传仍受 Bot API 50 MB 限制，超过上限时 save_it 会发送预览图，原始文件仍然保存在本地。

## 升级

自托管用户拉取最新镜像后重启即可，本版本没有配置项变更，也不需要新的 Typesense 迁移。
