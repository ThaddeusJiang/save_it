# save_it Weekly: 2026.9.3

Released 2026-09-03 · Version 2026.9.3 · Previous stable 2026.7.2

## Notes from the roadmap

This release adds no new commands. It fixes the things you already use: GIFs now play inline in Telegram, `/detail` is now `/info`, and links you send while the bot is offline are all saved after a restart instead of only the last one.

If you use save_it in a group chat to keep images and videos, you should feel all three immediately.

## Highlight 1: Saved GIFs arrive as playable animations

Saving a GIF — for example a GIF post from X — used to produce a downloadable file attachment: no animation in the chat, and GIFs above the upload limit were never delivered at all.

save_it now transcodes GIF content locally into a Telegram-friendly mp4 (libx264 / yuv420p / faststart, with probed width, height, and duration) and sends it as an animation. A useful side effect: transcoding usually shrinks a large GIF by an order of magnitude, so GIFs that previously failed the size check now go through. When ffmpeg is unavailable or the conversion fails, save_it falls back to the original GIF instead of dropping the message.

## Highlight 2: `/detail` is now `/info`

Reply to any saved photo or video with `/info` and the bot returns that item's provenance: source message URL, original URL, caption, title, description, keywords, and saved-at time. Missing fields are omitted.

The behavior and output are unchanged — the name is just shorter and more obvious. `/detail` is no longer supported; use `/info`.

## Highlight 3: Links sent while offline are no longer lost

If the bot was offline while you sent several links, only the newest one was processed after a restart; the earlier ones were discarded by Telegram's update queue.

The cause was the default polling worker starting with `offset: -1`, and a negative offset is a destructive queue operation for the Bot API. save_it now runs its own polling worker: the first `getUpdates` after startup omits the offset, so Telegram returns the earliest unconfirmed updates, each is dispatched, and the batch is acknowledged with `max(update_id) + 1`.

## Smaller improvements

- When Telegram rate limits a URL save, save_it retries once and tells you in chat when the retry is scheduled instead of failing silently.
- Google Drive backups use resumable uploads, so large files can recover from timeouts; successful, failed, and skipped-because-Drive-is-not-configured outcomes are all visible in the runtime logs.
- Google Drive login recovers on its own when Google rejects the OAuth client configuration: stuck pending device codes are cleared and actionable setup guidance is shown.

## Known limitations

- Short semantic queries such as `/search girl` can still return false positives; this is a limitation of the current Typesense image embedding model.
- Video uploads remain bound by the Bot API 50 MB limit. Above it save_it sends a preview image and still keeps the original file locally.

## Upgrading

Self-hosted deployments only need to pull the latest image and restart. This release changes no configuration and requires no new Typesense migration.
